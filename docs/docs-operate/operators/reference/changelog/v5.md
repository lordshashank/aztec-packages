## New features

### Per-block DA allocation multiplier

A new sequencer configuration option controls the per-block budget multiplier applied specifically to DA gas and blob fields, independently of the general L2 gas multiplier:

```bash
--perBlockDAAllocationMultiplier <value>   ($SEQ_PER_BLOCK_DA_ALLOCATION_MULTIPLIER)
```

**Default**: `1.5`

This higher default (vs. the L2 multiplier of 1.2) ensures that the largest supported transaction — a maximal contract class registration (~97k DA gas) — fits a single block under v5 mainnet geometry (72-second slots, 6-second blocks, 10 blocks per checkpoint). Operators may configure a higher value but not one below the network minimum of 1.5 (the sequencer will refuse to start).

### Network per-tx gas admission limit

Nodes now compute and advertise the maximum gas a single transaction may declare (`txsLimits.gas` in `getNodeInfo`). This is a network-wide limit derived from the timetable-derived blocks-per-checkpoint, the DA checkpoint budget (blob capacity net of encoding overhead), and the network-minimum per-block multipliers. Transactions exceeding this limit are rejected at RPC ingestion and gossip, rather than being silently skipped by proposers.

The sequencer and p2p layer enforce the same limit they advertise, so a transaction accepted over RPC is always admissible into a block.

### Sequencer multiplier validation at startup

The sequencer now fails startup — and rejects runtime config updates — if `SEQ_PER_BLOCK_ALLOCATION_MULTIPLIER` or `SEQ_PER_BLOCK_DA_ALLOCATION_MULTIPLIER` are set below the network minimums (1.2 and 1.5 respectively). A node configured below these values would admit transactions over RPC and gossip that its block builder can never pack, causing those transactions to be stranded.

Setting `SEQ_MAX_L2_BLOCK_GAS` or `SEQ_MAX_DA_BLOCK_GAS` below the network per-tx admission limit logs a warning but does not prevent startup — such a node simply builds smaller blocks and leaves larger transactions in the pool for other proposers.
